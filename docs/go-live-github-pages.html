Going live: cottageaesthetics.co.uk on GitHub Pages

Step-by-step instructions to connect your Name.com domain to the Cottage Aesthetics website.

This guide is written specifically for your domain, cottageaesthetics.co.uk, registered at Name.com. Every address and record below is the exact one to use — there is nothing to fill in or substitute. Work through the parts in order: GitHub first, then Name.com, then back to GitHub to finish.

1. What’s already done for you

All of the engineering work is finished and already switched on. You only need to do the steps in this guide once.

  • The website automatically rebuilds and republishes to GitHub Pages every time Purdi presses Publish (or Restore) in the Wixy admin panel — normally live within about two minutes.
  • Ordinary changes made to the website’s files on GitHub do not, by themselves, make anything go live. Only pressing Publish in the admin does that. This is a deliberate safety net so nothing appears on the public site by accident.
  • ca.cinnamons.uk remains the private staging address and the home of the admin panel. It is not indexed by search engines and is not the address the public will use — that will be cottageaesthetics.co.uk.
  • All that is left is to point GitHub at your domain, and point your domain at GitHub. That is what the rest of this guide walks through.

2. Part 1 — GitHub about 5 minutes

a. Confirm the domain setting

  1. Open the website’s repository: github.com/joshcomley/cottage-aesthetics-preview.
  2. Go to Settings → Secrets and variables → Actions → the Variables tab.
  3. Find WIXY_PUBLIC_DOMAIN. It should already hold cottageaesthetics.co.uk. If it is missing or different, click it and set the value to exactly cottageaesthetics.co.uk (no https://, no www., no trailing slash), then save.

b. Run the deploy once by hand

  1. Still in the repository, open the Actions tab.
  2. In the left-hand list, click Deploy to GitHub Pages.
  3. Click Run workflow, leave the branch as main, and click the green Run workflow button.
  4. Wait about a minute for the run to finish with a green tick.

c. Tell GitHub Pages about your domain

  1. Go to Settings → Pages (left sidebar, under “Code, planning, and automation”).
  2. Under “Build and deployment”, the source should already say GitHub Actions — nothing to change there.
  3. Under “Custom domain”, type cottageaesthetics.co.uk and click Save.
Expected warning GitHub will show that the DNS check has failed. That is normal at this point — you haven’t told Name.com about GitHub yet. That is Part 2, next.
Keep these two in step The WIXY_PUBLIC_DOMAIN variable (step a) and the “Custom domain” box (step c) must always hold exactly the same address. If either one is ever changed in future, change the other to match.

3. Part 2 — Name.com DNS about 10 minutes, plus waiting time

  1. Sign in at name.com → My Domains → cottageaesthetics.co.uk.

First: take the domain’s DNS control back from Wix

As of 10 August 2026, cottageaesthetics.co.uk’s DNS is still controlled by Wix, not by Name.com — even though the domain itself is registered at Name.com. That is why the old Wix website is still what visitors see today, and it is also why the records you add further down this page will have no effect until this is fixed: Name.com’s DNS Records page only takes effect once Name.com is actually the one answering DNS lookups for the domain, and right now Wix is.

  1. Still on cottageaesthetics.co.uk’s page at Name.com, find the Nameservers section (sometimes shown as part of “Domain Details”).
  2. Switch it back to Name.com’s own default nameservers — look for wording like “Use Name.com default nameservers”, or a toggle between “Name.com default” and “Custom”. The exact wording can vary; the goal is simply that Name.com, not Wix, ends up listed as the domain’s nameserver provider.
  3. Save the change.
This is the actual switchover moment Once this change spreads across the internet, the old Wix site will stop being what visitors see at cottageaesthetics.co.uk — that is the whole point of this step. Do it in the same sitting as adding the records further down this page, so the new site takes over as soon as the old one drops away, rather than the domain going quiet in between. Nameserver changes usually spread within a few hours; occasionally it can take 24–48 hours.

The domain itself — cottageaesthetics.co.uk — is registered at Name.com, not at Wix. Nothing about this step, or anything at Wix, affects who owns it. Once the new site is live on the domain, the Wix subscription can be cancelled with no risk to the domain at all.

You know it worked when this command lists Name.com’s own nameservers, not Wix’s:

nslookup -type=NS cottageaesthetics.co.uk 8.8.8.8

While it still lists anything ending in wixdns.net, the switch hasn’t spread yet — wait and check again.

You do not have to wait for that switch to spread before continuing. Carry straight on to the records below and add them at Name.com now, in the same sitting — Name.com lets you stage records on its DNS Records page immediately, even before the nameserver switch has taken effect. They will simply start working on their own once it does.

Next, remove anything that conflicts

On cottageaesthetics.co.uk’s DNS Records page:

  • Delete any existing A, AAAA, ANAME or ALIAS record on the bare domain (Host column blank, or showing @).
  • Delete any existing CNAME record on www.
  • Delete any of Name.com’s own default “parking” records, if present.
  • Switch off Domain Forwarding / URL Forwarding for this domain, if it is turned on.

Then add these records

Leave the Host column empty for the bare domain (some interfaces show this as @ automatically). Set TTL to 300 seconds if you are asked.

TypeHostAnswer / Value
A(blank)185.199.108.153
A(blank)185.199.109.153
A(blank)185.199.110.153
A(blank)185.199.111.153
AAAA(blank)2606:50c0:8000::153
AAAA(blank)2606:50c0:8001::153
AAAA(blank)2606:50c0:8002::153
AAAA(blank)2606:50c0:8003::153
CNAMEwwwjoshcomley.github.io

That is eight records in total (four A, four AAAA) for the bare domain, plus one CNAME for www. The CNAME value is exactly joshcomley.github.io — no https://, no trailing slash, and it does not include the repository name.

Still seeing Wix, or something else, under Nameservers? If you completed “First: take the domain’s DNS control back from Wix” above, the nameservers should now be Name.com’s own defaults, and the records page above is the right — and only — place to make these edits. If “Domain Details” still shows anything ending in wixdns.net, that step either wasn’t completed or hasn’t finished spreading yet: go back and do it, rather than adding these records inside Wix’s own DNS manager instead. Editing DNS inside Wix would keep the site dependent on Wix, which is the opposite of what this whole guide is for. If “Domain Details” instead shows a different third-party nameserver you recognise (for example Cloudflare) and that was a deliberate choice, make these same DNS edits at that provider instead.

4. Part 3 — back in GitHub

  1. Return to Settings → Pages on the repository (the same page as Part 1c).
  2. DNS changes can be immediate or take a few hours to reach everywhere. Refresh the page from time to time — the domain check turns green automatically once your records have arrived. To check progress yourself without waiting on GitHub’s own refresh, use dnschecker.org, or open a terminal and run: 
    nslookup cottageaesthetics.co.uk 8.8.8.8
  3. Once the check is green, tick Enforce HTTPS. GitHub issues a certificate automatically — this usually takes a few minutes, occasionally up to about an hour, and rarely up to 24 hours.
Recommended, not required

Verifying your domain with GitHub stops anyone else from ever being able to take it over on GitHub Pages (for example if the repository were ever deleted). It takes a couple of extra minutes:

  1. Click your profile picture (top right of any GitHub page) → Settings → Pages (left sidebar, under “Code, planning, and automation”) → Add a domain.
  2. Enter cottageaesthetics.co.uk → Add domain.
  3. GitHub shows a TXT record to add. At Name.com, add it exactly as shown: Type TXT, Host _github-pages-challenge-joshcomley, Answer/Value exactly the code GitHub gives you (copy it precisely).
  4. Wait for it to appear (dnschecker.org, or nslookup -type=TXT _github-pages-challenge-joshcomley.cottageaesthetics.co.uk 8.8.8.8), then click Verify back on GitHub.

5. Part 4 — check it worked

  • https://cottageaesthetics.co.uk loads the site with a padlock (secure) icon.
  • The old Wix version of the site no longer appears at cottageaesthetics.co.uk — expected, and the whole point of this changeover.
  • https://www.cottageaesthetics.co.uk redirects to the same place.
  • https://joshcomley.github.io/cottage-aesthetics-preview/ also redirects to your domain.
  • https://cottageaesthetics.co.uk/robots.txt shows “Allow” and a line pointing at the sitemap.
  • https://cottageaesthetics.co.uk/sitemap.xml lists the site’s pages.
  • A made-up address, for example https://cottageaesthetics.co.uk/this-page-does-not-exist, shows the site’s own styled “page not found” message, not a blank GitHub error page.

The real test: make a small change in the Wixy admin (for example, edit a line of text) and press Publish. Reload cottageaesthetics.co.uk after about two minutes and confirm the change is there.

6. Troubleshooting

SymptomWhat’s happeningWhat to do
You added the records at Name.com but absolutely nothing changed The domain’s nameservers still point at Wix — the “First: take the domain’s DNS control back from Wix” step (Part 2) either wasn’t done, or hasn’t finished spreading yet Run nslookup -type=NS cottageaesthetics.co.uk 8.8.8.8. If it lists anything ending in wixdns.net, do (or redo) that step, then wait and check again
The DNS check on the Pages settings page won’t turn green Either the records haven’t reached everywhere yet, or something doesn’t match Wait longer (up to 24 hours); re-check every record against Part 2 exactly — a leftover old record, or the wrong Host column, is the most common cause
GitHub says “Domain is already taken” A safety feature — can happen if the domain was ever connected to a GitHub Pages site before Do the domain verification steps in Part 3 (the TXT record), then try adding the custom domain again
The HTTPS certificate is stuck, or never appears It only starts being issued once the DNS check has turned green Wait for the DNS check first; if it has been green for over an hour with still no certificate, remove the custom domain in Settings → Pages, then add it again to restart the process
The site shows old content Either the automatic deploy hasn’t run since the last Publish, or the WIXY_PUBLIC_DOMAIN variable isn’t set Check the Actions tab for a recent green “Deploy to GitHub Pages” run; re-check the variable (Part 1a)
www.cottageaesthetics.co.uk doesn’t redirect The www CNAME record is missing or incorrect Re-check the CNAME record in Part 2
The site looks slightly wrong at the joshcomley.github.io address, but fine at cottageaesthetics.co.uk Expected, and nothing to fix The temporary github.io address hosts the site inside a sub-folder, which by design breaks some internal links there. Always judge the site by cottageaesthetics.co.uk, never by the github.io address

7. Afterwards

There is nothing to maintain day to day. Every time Publish is pressed in the Wixy admin, the public site rebuilds and redeploys automatically, usually live within a couple of minutes.

If the domain ever needs to change in future, update it in two places together — the WIXY_PUBLIC_DOMAIN variable (Part 1a) and the Pages “Custom domain” box (Part 1c) — then set up matching DNS records at whichever provider hosts the new domain, following Part 2’s pattern.
