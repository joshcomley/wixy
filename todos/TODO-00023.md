## Discovered mid-flight (not in the original brief)

- The site repo's `github-pages` deployment environment had a pre-existing custom branch
  policy (`gh-pages`, `main` only) that would have silently blocked every automatic
  `wixy-live`-triggered deploy (GitHub's environment gate checks the triggering ref, not what
  a checkout step fetches) — invisible to any PR's own CI since `pages.yml` never triggers on
  `pull_request`. Fixed live via `gh api -X POST .../environments/github-pages/
  deployment-branch-policies -f name=wixy-live -f type=branch` (needed the operator's token —
  the fleet bot-PAT is deliberately admin-scope-less and 403s on this). Recorded in wixy
  decisions/00126, site-repo decisions/00013, and wixy docs/ai/runbook.md.
